# hstring：手写字符串类

> 状态：已结束项目。网站记录历史实现和学习收获，暂无继续开发计划。

## 这个案例要回答的问题

- 一个自定义字符串对象如何管理字符缓冲区？
- 构造、拷贝、拼接、查找、删除和替换分别如何改变数据？
- 什么情况下会重新分配缓冲区？
- 设计目标和当前代码之间有哪些差异？

## 设计目标与当前实现

原始说明希望用缓冲区减少频繁分配，并限制拼接、替换等操作的分配次数。当前代码确实维护 buffer、buffer_size 和 data_length，并按 128、256、512……的容量级别扩容；但代码没有引用计数和零拷贝机制，operator+ 仍会为结果创建新缓冲区。因此页面把“设计目标”和“代码事实”分开呈现。

## 主线执行路径

1. 构造函数为对象分配初始缓冲区，并把字符串复制进去。
2. operator+ 计算总长度，创建结果对象的缓冲区，再复制左右两段字符。
3. find 以暴力匹配扫描首次出现的位置。
4. operator- 先复制对象，再用 memmove 删除首次出现的子串。
5. replace 根据新旧长度选择原地移动或重新分配。
6. operator=(int) 把整数倒序拆位，再写回字符缓冲区。

## 已标出的缺陷

### 1. 设计说明和代码不一致

《hstring 字符实现要求》提到引用计数、零拷贝和性能提升数字，但当前头文件和实现没有对应机制或基准数据。这些内容只能作为历史设计目标，不能当成已完成能力。

### 2. find 的失败值类型不安全

find 返回 size_t，却用 return -1 表示失败。调用方收到的是无符号的大整数；operator- 又把它窄化到 int，结果依赖实现，应该在后续重构时统一返回类型和失败约定。

### 3. replace 的负数检查无效

replace(size_t pos, ...) 中的 if (pos < 0) 永远不会成立，因为 size_t 是无符号类型。越界判断需要改用无符号范围条件。

### 4. operator+ 没有复用已有缓冲区

两个 operator+ 都通过 no_alloc_tag 创建结果，再无条件 new char[...]。这与“只有超出初始缓冲区才分配”的原始目标不同；当前实现最多控制了结果对象的一次分配，并没有做到零分配拼接。

### 5. operator- 的位置类型过窄

find 的位置先保存到 int pos，而字符串长度和查找结果使用 size_t。当字符串规模超过 int 可表示范围时，这个转换可能丢失信息。

## 复盘

这个项目最适合用来学习手动内存管理、拷贝语义、运算符重载和边界检查。对网站来说，最重要的不是把它包装成“高性能字符串”，而是把缓冲区状态、数据移动和实现缺陷画清楚。
